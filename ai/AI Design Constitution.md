# AI Design Constitution
Version: 1.0
Project: Enterprise ERP Platform
Owner: Product Design

# Purpose

This document defines the permanent design principles for this project.

These principles take precedence over aesthetic trends, AI-generated conventions, and subjective design choices.

Every implementation must comply with this constitution.

---

# Product Identity

This is an Enterprise ERP Platform.

It is designed for institutions that manage complex operational workflows such as:

- Schools
- Colleges
- Universities
- Corporate Training Institutes
- Educational Trusts
- Multi-campus Organizations

The interface must communicate:

- Trust
- Stability
- Professionalism
- Operational Excellence
- Long-term Reliability
- Product Maturity
- Simplicity
- Confidence

It must never communicate:

- Experimental
- Futuristic
- Gaming
- Crypto
- Consumer Social App
- AI Startup Landing Page
- Marketing-heavy Product

---

# Design Philosophy

The product should feel like software people depend on every day.

It should not feel like software people admire for five minutes.

The interface must prioritize:

1. Clarity
2. Usability
3. Information Hierarchy
4. Workflow Efficiency
5. Consistency
6. Accessibility

Visual decoration is always secondary.

---

# Core Principles

## Product Before Decoration

Real product interfaces create trust.

Actual screenshots are always preferred over illustrations.

Real workflows are preferred over conceptual graphics.

Never add decoration that does not communicate product value.

---

## Typography Before Effects

Typography is the primary design tool.

Hierarchy should be created using:

- Size
- Weight
- Spacing
- Alignment

Never rely on:

- Shadows
- Bright colors
- Animations
- Decorative backgrounds

to create hierarchy.

---

## White Space Is Functional

Whitespace is not empty space.

Whitespace groups information.

Whitespace improves scanning.

Whitespace creates visual rhythm.

Never fill empty areas with decorative elements.

---

## Every Pixel Must Have Purpose

Every visual element must answer at least one question.

Examples:

Does it improve readability?

Does it explain functionality?

Does it increase trust?

Does it improve navigation?

If the answer is no, remove it.

---

## Content First

Content is the interface.

Decorative components must never overpower:

- Product screenshots
- Workflow explanations
- Feature descriptions
- Customer proof
- Implementation details

---

# Layout Philosophy

Prefer:

Simple layouts

Strong grids

Predictable spacing

Large readable typography

Content grouping

Clear hierarchy

Avoid:

Overlapping cards

Broken grids

Floating objects

Random asymmetry

Visual clutter

---

# Component Philosophy

Components are tools.

Not decoration.

Every component should be:

Reusable

Predictable

Consistent

Accessible

Responsive

Maintainable

Never create one-off visual components.

---

# Motion Philosophy

Motion should explain interaction.

Motion should never exist for decoration.

Allowed:

Hover feedback

Page transitions

Expandable sections

Loading states

Focus states

Not Allowed:

Constant floating

Infinite animations

Animated backgrounds

Parallax

Random movement

Decorative motion

---

# Color Philosophy

Color communicates meaning.

Color should indicate:

Primary actions

Status

Alerts

Selection

Focus

Color should never exist purely for decoration.

---

# Trust Indicators

The interface should emphasize:

Real product screenshots

Institutional workflows

Security

Implementation process

Customer success

Operational capability

Deployment confidence

Scalability

These build trust more effectively than decorative visuals.

---

# AI Design Smells

If the implementation resembles any of the following, reconsider the design.

- Glassmorphism
- Gradient blobs
- Neon gradients
- Floating badges
- Oversized rounded corners
- Excessive shadows
- Every card animated
- Gradient text
- Random icon backgrounds
- Hero illustrations unrelated to the product
- Decorative statistics
- Generic SaaS feature grids
- Empty whitespace filled with shapes
- Repeated card layouts
- Excessive use of Lucide icons
- Marketing language with no supporting visuals
